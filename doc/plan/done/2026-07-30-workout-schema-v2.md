## 1. 範圍

只動**型別與匯入解析**，不動畫面層以外的既有行為。與批次 B（打卡 checklist 與日曆）
有交集但**先做這一份**——批次 B 的打卡 UI 要知道「今天有兩個選項」才設計得對，
順序反過來會做白工。

## 2. 新課表放不進 v1 的地方

| # | 新課表的結構 | v1 為何放不下 |
|---|---|---|
| 1 | 週一「15 分鐘椅子核心與上肢」**或**「5 分鐘隱形坐姿核心」；週四「MV 舞蹈」**或**「坐姿飛輪」；週末「戶外散步」**或**「居家放鬆」 | `requirement: 'any-one'` 是**跨星期**擇一（六或日），不是同一天內的**活動**擇一 |
| 2 | 週二、三是 NEAT 日，「不強求大課表」 | 會被算成應運動日，達成率分母膨脹 |
| 3 | 廚房 1 分鐘微肌力「**擇一**執行」（伏地挺身 或 靠牆靜止收縮） | 階段內的項目一律視為全做 |
| 4 | MV 舞蹈「10–15 分鐘」 | `durationSeconds` 是單一數字，沒有範圍 |
| 5 | 週一與週五共用同一套動作，只差組數（2 組 vs 3 組）與熱身長度 | 可用複製解決，見 §3.5 |

## 3. Schema v2 變更

`WORKOUT_SCHEMA_VERSION` 由 `1` 升為 `2`。

### 3.1 `PlanGroup.variants`：同日擇一（對應挑戰 1）

```
PlanGroup
  ├ variants: PlanVariant[]     ← 新增，取代原本的 stages
  └ (移除) stages

PlanVariant
  ├ id, label
  ├ summary?
  ├ estimatedMinutes: NumRange
  └ stages: Stage[]
```

只有一種內容的日子就是**單一 variant**，不必特例。
`variants.length > 1` 時，打卡要選一個。

`WorkoutLog` 新增 `variantId?: Id`，記錄當天實際做了哪個選項。
這對批次 C 有價值——跳舞與飛輪的比例、極速版與完整版的比例，都是使用者的真實行為。

### 3.2 `PlanGroup.countsTowardQuota`：NEAT 日（對應挑戰 2）

```
PlanGroup.countsTowardQuota: boolean
```

週二、三設 `false`。`computeMonthStats()` 計算「應運動日配額」時跳過這些日子，
但它們的打卡**仍然計入「實際運動日」**。

理由：達成率要反映的是自律程度，把「本來就不要求」的日子放進分母只會讓數字失真；
但媽媽真的在廚房動了，運動日佔比不該漏掉她。

### 3.3 `Stage.selection`：階段內擇一（對應挑戰 3）

```
Stage.selection: 'all' | 'choose-one'   // 預設 'all'
```

廚房 1 分鐘微肌力設 `'choose-one'`，打卡時兩個動作只勾一個即可算完成。

與 3.1 的分工：**整份課表二選一**用 `variants`（週一的 15 分鐘模組 vs 5 分鐘隱形核心，
是完全不同的兩節課）；**單一階段內的動作二選一**用 `selection`。
兩者層級不同，不能互相取代。

### 3.4 `StageItem.durationSeconds` 改為 `NumRange`（對應挑戰 4）

```
durationSeconds?: number      →   durationSeconds?: NumRange
```

MV 舞蹈存 `{ min: 600, max: 900 }`。固定秒數（拳擊 45 秒）就只給 `min`，
與既有 `reps` / `rounds` 的處理方式一致。

**打卡輸入單位**：`durationSeconds.min >= 120` 時 UI 以**分鐘**為輸入單位，
否則用秒。使用者已明確要求 MV 舞蹈要能改時間、單位是分鐘。
不另外加欄位標記單位——由數量級推導就夠，多一個欄位反而要維護一致性。

### 3.5 週一／週五共用動作（挑戰 5，不改 schema）

兩天是不同 `PlanGroup`，各自持有自己的 `Stage`（週一 `rounds: 2`、熱身抬腿 60 秒；
週五 `rounds: 3`、熱身抬腿 120 秒）。動作本身透過 `exerciseId` 指向**同一筆 `ExerciseDef`**，
所以動作庫不重複、進步趨勢也不會被拆成兩條線。

重複的只有規格，這是刻意的——課表版本是歷史事實，讓兩天各自持有自己的規格，
日後只調整其中一天時不會互相污染。

### 3.6 `WorkoutPlan.avoidances`

```
WorkoutPlan.avoidances: string[]   // ['深蹲', '跳躍', '爬樓梯']
```

新課表把「完全避開深蹲、跳躍與爬樓梯」列為最高原則。它與 `medicalNotes`（病史）性質不同：
這是**可機器檢查的規則**——匯入新版課表時，可以掃描動作名稱與步驟文字，
命中禁忌詞就跳警告。AI 重出課表最容易犯的錯就是悄悄放回被排除的動作。

## 4. 新課表對應結構

### 4.1 星期對照

| 星期 | `label` | `requirement` | 計入配額 | variants |
|---|---|---|---|---|
| 一 | 讀書會 / 居家備戰日 | `all` | ✅ | ①椅子核心與上肢（極速版）+ 氣球放電 20m ②隱形坐姿核心 5m |
| 二、三 | 買菜備料煮飯日 | `all` | ❌ | 單一：廚房 NEAT 日 |
| 四 | MV 舞蹈 / 平路飛輪日 | `all` | ✅ | ①MV 舞蹈 10–15m ②坐姿低阻力平路飛輪 10m |
| 五 | 輕鬆晚餐 / 放鬆日 | `all` | ✅ | 單一：墊上核心與椅子肌力（完整版）20m |
| 六、日 | 家庭日 / 輕活動 | `any-one` | ✅ | ①全家戶外散步 20m ②居家放鬆 15m |

**七天全部被涵蓋，`restWeekdays` 為空**——這份課表沒有「完全休息日」。
週二、三是彈性日（`countsTowardQuota: false`）而非休息日，兩者不同：
彈性日仍會出現在今天卡片與月曆上，只是不進達成率分母。

單一 variant 的日子（週二三、週五）在 JSON 中直接寫 `stages`，
解析器會包成單一 variant 並**沿用群組 label 當 variant label**
（因此週五的 variant 名稱是「輕鬆晚餐 / 放鬆日」而非本表的描述文字）。
單一 variant 時 UI 不顯示切換鈕，不影響呈現。

### 4.2 主訓練模組（週一極速版 / 週五完整版）

| 階段 | 週一（20m） | 週五（20m） |
|---|---|---|
| 熱身 | 2m：抬腿 60s、繞環 60s | 3m：抬腿 120s、繞環 60s |
| 主訓練 | `rounds: 2`，組間休息 60s | `rounds: 3`，組間休息 60s |
| 溫和拉伸 | 3m（同下） | 3m（同下） |
| 氣球放電 | 5m（決議 3） | — |

主訓練四個動作（兩天相同）：

| # | 動作 | measureType | 規格 |
|---|---|---|---|
| 1 | 坐姿核心收縮 | `reps` | `reps: {min:10}`、`holdSeconds: 5` |
| 2 | 椅子扶手伏地挺身 | `reps` | `reps: {min:8, max:12}` |
| 3 | 墊上臀橋 | `reps` | `reps: {min:12}`、`holdSeconds: 2` |
| 4 | 椅子坐姿拳擊 | `time` | `durationSeconds: {min:45}` |

拉伸兩個動作：

| # | 動作 | measureType | 規格 |
|---|---|---|---|
| 1 | 坐姿大腿後側伸展 | `hold` | `holdSeconds: 45`、`perSide: true` |
| 2 | 坐姿胸部伸展 | `hold` | `holdSeconds: 45`、`sets: 2` |

**匯入規則要點**：「循環 3 組」是 `Stage.rounds`，「每組 10 次」是 `StageItem.reps`，
動作層的 `sets` **留空**，否則會被算成 3×3。
唯一填 `sets` 的是坐姿胸部伸展（單一動作重複 2 次，不在循環內）。

### 4.3 其他 variant 的內容

- **隱形坐姿核心 5m**：腹橫肌等長收縮（`reps: 10`、`holdSeconds: 10`）、
  交替提腳跟（`reps: 30`）
- **廚房 NEAT 日**：三個階段——①NEAT 廚房日常（描述型，無項目）
  ②廚房 1 分鐘微肌力（`selection: 'choose-one'`：流理台伏地挺身 8–10 次 ／
  靠牆靜止收縮 30 秒 ×2）③睡前床上放鬆（抱膝 40 秒 ×2、脊椎扭轉 45 秒 `perSide`）
- **坐姿飛輪 10m**：`time`、`durationSeconds: {min:600}`、`resistance: '0'`，
  踏頻 60–70 RPM 放 `note`
- **MV 舞蹈**：`time`、`durationSeconds: {min:600, max:900}`
- **居家放鬆 15m**：頭頸繞環 1m、坐姿貓牛 2m、坐姿胸部伸展 2m、仰臥抱膝 3m、
  全家拍氣球 7m
- **戶外散步 20m**：`time`、`durationSeconds: {min:1200}`

### 4.4 備用課表（`fallbackRoutines`）

「隱形坐姿核心」「廚房 1 分鐘微肌力」「睡前床上放鬆」三份**同時**放進 `fallbackRoutines`，
讓任何忙碌日都能主動選用，不限於它們原本綁定的星期。
內容與對應 variant 相同，`exerciseId` 指向同一批動作定義。

### 4.5 動作庫（實際 20 筆）

熱身 2、主訓練 4、拉伸 2、隱形核心 2、廚房 2、睡前 2、居家放鬆 2（頭頸繞環、坐姿貓牛）、
活動型 4（MV 舞蹈、坐姿飛輪、戶外散步、全家拍氣球）。

**「NEAT 廚房日常熱量消耗」不建立描述型動作**（原規劃有，實際捨棄）。
該階段以 `items: []` 呈現，只靠 `Stage.note` 說明「備料、站立、提重物本身就是消耗」。
理由：它沒有可執行的動作，硬造一筆會污染動作庫，也會在批次 C 的進步趨勢多出一條沒有意義的線。

> **對批次 B 的影響**：這是課表中唯一一個**沒有任何可勾項目的階段**。
> 「一鍵全部完成」碰到它要算完成還是略過，需與
> [roadmap 批次 B 的待決議](../2026-07-28-workout-roadmap.md)一併確認。

跨 variant 共用的：坐姿胸部伸展（主訓練拉伸／居家放鬆）、
仰臥抱膝（睡前放鬆／居家放鬆，GEM 用了「仰臥單/雙膝抱胸」與「仰臥抱膝放鬆」兩個名字，
**應合併為一筆**）。

不可合併：椅子扶手伏地挺身 vs 流理台扶手伏地挺身（器材與角度不同，是兩個動作）。

### 4.6 器材

GEM 這版有結構化清單，直接進 `ExerciseDef.equipment`：
BH 飛輪機、室內專屬平底運動鞋、穩固靠背椅子（無輪、靠牆）、瑜珈墊（6–8mm 防滑）、一般氣球。

「無輪子、靠牆放置」「務必穿專屬運動鞋」既是器材規格也是安全條件，
**兩邊都要放**（`equipment` 與 `cautions`）。

### 4.7 醫療與防護

- `medicalNotes`：二尖瓣脫垂（心悸／胸悶／喘不過氣 → 立即停止坐下休息喝水）、
  膽結石（右上腹鈍痛 → 半躺休息，切勿強行運動）
- 群組層 `cautions`：舞步遇跳躍／深蹲改原地踩步；飛輪零阻力、不站姿抽車、務必穿鞋；
  飛輪時左腳踝有酸痛立即下車改椅子運動
- 動作層 `cautions`：不聳肩、腰不下塌、不憋氣、膝蓋不超過腰部、臀橋不壓迫膝關節

## 5. 遷移

localStorage 目前只有第 1 版課表與少量打卡，成本極低：

- `localRepository` 讀取時若 `schemaVersion === 1`，把 `PlanGroup.stages` 包成
  單一 variant（`label` 沿用群組 label），`countsTowardQuota` 補 `true`，
  `Stage.selection` 補 `'all'`，`durationSeconds` 數字包成 `{ min: n }`
- 舊 `WorkoutLog` 的 `variantId` 留空，代表「當時只有一個選項」
- 遷移後回寫，`schemaVersion` 更新為 2

舊課表**不解除鎖定**，遷移只補結構、不改內容。

### 7.1 決議 3 對週一的影響

週一原為 15 分鐘（熱身 2m + 主訓練 2 組 10m + 拉伸 3m），
加入「全家拍氣球 5m」後總時長為 **20 分鐘**，`estimatedMinutes` 更新為 `{ min: 20 }`。

氣球放電放在主訓練之後、拉伸之前？還是整節課最後？
——**放在最後**（拉伸之後），因為它是家庭活動、性質接近收操後的自由活動，
且拉伸緊接主訓練才有意義。

`全家拍氣球` 動作定義與週末「居家放鬆」共用同一筆（`Balloon Keep-Up`），
週一 5 分鐘、週末 7 分鐘，規格各自持有。

### 7.2 決議 4 的補充

GEM 認為兩者是不同動作，動作庫維持兩筆：

- **坐姿核心收縮 (Seated Vacuums)**：主訓練用，停留 5 秒 ×10 次
- **坐姿腹橫肌等長收縮 (Seated Abdominal Bracing)**：隱形坐姿核心用，停留 10 秒 ×10 次

代價是批次 C 的進步趨勢會是兩條線。若日後判定應合併，
因為 `ExerciseDef` 以名稱共用，屆時改名即可自然合併，不需要資料遷移。

> **待補**：使用者提到 GEM 有附「兩者不同」的原因與說明，但該段文字未隨訊息附上。
> 若其中包含影響 `targetMuscles` 或 `cautions` 的細節，補上後再調整動作定義。

## 9. 實作結果（2026-07-30）

### 9.1 與計畫的偏離

- **遷移邏輯抽成 `src/services/workout/migrate.ts`**，而非寫在 `localRepository.ts`。
  理由：純函式才能用 esbuild 腳本單獨驗證，實際也驗到了（12 項）。
  `localRepository` 改為所有課表讀取都走 `readPlans()`，就地升級並回寫，
  其餘程式碼永遠只看得到目前版本的形狀。
- **`importAll()` 順帶放寬**：原本備份檔版本不等於當前版本就擋下，
  現在改為「低於當前版本 → 遷移後匯入，高於 → 擋下」。
  否則使用者手上的 v1 備份檔會直接變成廢檔。
- **`ModalView` / `ConfirmModalView` 未加 `overscroll-behavior`**（上一批的事，
  此處僅註記）。
